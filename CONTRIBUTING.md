# Внесение изменений

[На главную](README.md)

## Ориентиры

Основная версия находится в `Analitics/1/Arcanomics`. `Analitics/igra.py` и сохранённая HTML-страница относятся к ранним версиям; не переносите из них код без проверки совместимости состояния и форматов данных.

Перед изменением модели прочитайте [архитектуру](docs/ARCHITECTURE.md), [логику](docs/SIMULATION.md), [топологию](docs/TOPOLOGY.md) и [известные ограничения](docs/KNOWN_ISSUES.md). Изменения документации и изменения поведения удобно оформлять отдельными коммитами, чтобы их можно было проверить независимо.

## Документация и структура

- Поддерживайте ссылки из корневого README и вложенного README приложения.
- Описывайте фактический код; планируемые возможности обозначайте явно.
- Не перемещайте `src/`, `data/`, `lib/` и приложение целиком без проверки путей Python, порядка JS и ссылок HTML.
- Сохраняйте исторические CSV и отчёты отдельно от новых результатов. Не заменяйте их случайно при проверке запуска.
- Новые кэши и локальные Python-окружения исключены через `.gitignore`. Уже отслеживаемые артефакты этим не удаляются.

## Что важно при изменении кода

Сохраняйте порядок загрузки `init → weather → economy → logistics → simulation`, либо явно обновляйте и проверяйте контракт между модулями. Товары, поля CSV, единицы «за игровой час» и порядок «местная экономика → логистика → сводки» являются частью интерфейса модели.

Изменения `cities.json`, ограничений выборки или порядка регионов меняют граф. Для текущих входов ожидаются 17 городов и 23 дороги; идентификаторы `edge_N` зависят от порядка построения.

## Проверка изменений

Для правок документации проверьте относительные ссылки, соответствие описаний исходникам и состав diff:

```bash
git diff --check
git diff --stat
git diff --name-status
git status --short
```

До `git add` новые неотслеживаемые файлы видны в `git status`, но не в обычном `git diff`. После добавления конкретных файлов проверьте `git diff --cached --check` и `git diff --cached --name-status`.

Если код меняться не должен, в diff должны быть только согласованные Markdown-файлы и служебные настройки репозитория. Существующие `.py`, `.js`, HTML, JSON, CSV, библиотеки и отчёты должны сохранить содержимое.

Для изменений реализации дополнительно проверьте генератор в отдельной копии, JavaScript в браузере и анализ сохранённых CSV. Успех Python-генерации не подтверждает работоспособность симуляции; текущая ошибка `updateRoadLogistics()` описана отдельно. Для повторяемого старта перезагружайте страницу.

После исправления полного цикла проверяйте соответствие ожидаемой длительности, согласованность `run_id`, неотрицательные остатки, баланс `fulfilled_demand + unmet_demand = demand_per_hour`, топологию и схемы выгружаемых CSV. Не скрывайте прежние ошибки за успешной проверкой синтаксиса.
